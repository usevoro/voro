# VORO

<!-- impeccable:product-schema 1 -->

## Platform

web

React UI inside a sandboxed Electron desktop application, macOS first. Desktop window minimum 1080 × 700; no mobile product is currently shipped.

## Users

The individual reviewing 3D assets in their own project folders, as established in the user-provided PRD.

## Product Purpose

Browse assets, inspect their geometry and animation, leave actionable comments, and record review status without importing or uploading a project.

## Positioning

Reviews are versioned sidecar files beside their source assets. They travel with the project's existing filesystem or version-control workflow.

## Operating Context

Open a folder, scan and filter its assets, select a thumbnail, inspect a model, and save feedback. Reopen the folder to continue. The normal workflow is offline.

## Capabilities and Constraints

Preserve the implemented catalog, viewer, comments, conflict handling, keyboard controls, native dialogs, and local-only security boundaries. GLB/glTF preview support; other recognized formats are reviewable without previews. No collaboration accounts, source editing, authoring-tool equivalence, or speculative integrations.

## Brand Commitments

The user explicitly requested a bespoke UI and a whole branding suite, replacing the generic initial visual treatment. The PRD used Asset Reviewer. The user subsequently rejected that generic name and asked for a bold, creative, abstract brand name. The implemented naming direction is VORO, pronounced VOH-roh. New visual choices are design proposals implemented under that redesign request, not historical brand facts.

## Evidence on Hand

PRD.md, README.md, docs/IMPLEMENTATION.md, the working Electron app and generated fixtures. test-results/ contains prior verified screenshots. No customer logos, testimonials, commercial claims, or real production models have been supplied.

## Product Principles

- Let source assets lead.
- Keep review decisions and persistence legible.
- Preserve work across selection and external changes.
- Use native, familiar desktop controls.

## Accessibility & Inclusion

Accessible control names, visible focus, keyboard navigation, sufficient contrast, reduced-motion support, and clear error and saving states, per the PRD and implementation.

## Artistic direction update

The user explicitly rejected the technical branding and requested a game-development vibe, more artsy. The current direction is a game-jam artbook: playful mascot, expressive type, plum and apricot palette, and painted key art. Keep VORO and all product workflows.
