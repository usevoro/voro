# VORO landing page

This persuasion surface inherits the game-jam artbook world in ../DESIGN.md and the scope in ../docs/LANDING_PAGE_PRD.md. It does not change the desktop design system.

Audience: indie game developers and 3D artists reviewing assets in a project folder. The visitor should understand the local preview → feedback → saved sidecar workflow and find the right desktop release.

First viewport: a generous two-page artbook composition. An expressive plum headline and concrete product description sit beside VORO’s existing gouache world. The next fold reveals a real, readable application capture, not a reconstructed UI. Warm paper, apricot, lilac, Bricolage Grotesque, DM Sans, and the original sprout retain the established identity.

The page moves from imagination to working proof: hero, interactive choice of actual full-view/gallery screenshots, three steps, portable feedback, platform availability, FAQ, and a dark plum close. The signature interaction switches between inspecting a model and browsing the collection; both views remain available without JavaScript. Motion is limited to a brief opacity change on the demonstration. Reduced motion disables it. Mobile stacks the artbook and gives the app capture an explicit full-size image link.

No invented users, testimonials, integrations, pricing, release dates, or open-source claims. The source repository is private. Public GitHub links currently resolve to the organization. Platform downloads appear only from explicitly mapped, verified public release assets. Unknown stars are omitted. The local review preview is noindex. Vercel is the deployment target for the static build; no Nitro runtime is required. Preview deployments stay noindex, and public indexing requires explicit production configuration. Noindex controls indexing, not access; restricted hosted previews require deployment protection.
